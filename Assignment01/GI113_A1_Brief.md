สิ่งที่ล็อกไว้มีแค่ **concept ทางโปรแกรมมิ่งที่ต้องโชว์ให้เห็นว่าใช้เป็น** (ตารางด้านล่าง) — ไม่ใช่ตัวเลข ข้อความ หรือลำดับการเขียนโค้ด ไม่มีข้อกำหนดเรื่อง input จากคีย์บอร์ด — โปรแกรมนี้กำหนดค่าทุกอย่างในโค้ดเลย (`Console.ReadLine` ยังไม่ต้องใช้ในนี้)

## ✅ สิ่งที่ต้องมีอยู่ในโค้ด (ไม่ใช่ลำดับที่ต้องทำตาม)

ต้องมีครบทุกแถว แทรกอยู่ตรงไหนของโปรแกรมก็ได้ ลำดับเป็นเรื่องของคุณ:

| Concept | ต้องมีอะไร |
|---|---|
| **ชนิดข้อมูล 6 แบบ** | `string`, `char`, `int`, `float`, `double`, `bool` — แต่ละตัวมีความหมายจริงกับธีมที่เลือก ไม่ใช่ใส่มั่วให้ครบ |
| **`const`** | ประกาศ 1 ตัว ใช้กับอะไรก็ได้ที่ "ไม่ควรเปลี่ยนตลอดทั้งโปรแกรม" (ชื่อเกม, ชื่ออาชีพ, ค่าคงที่ที่เข้ากับธีมของคุณ) |
| **`var`** | อย่างน้อย 2 ตัว รวม `string`/`char` อย่างน้อย 1 ตัวที่ให้ compiler เดาชนิดเอง (ห้ามใช้ `var` กับตัวเลขล้วนๆ ที่ไม่ต้องคิดอะไร) |
| **Implicit Conversion** | เอาตัวแปร `int` ของคุณไปแปลงเป็น `double`/`float` แบบไม่มี cast เลย อย่างน้อย 1 จุด แล้วพิมพ์ค่าที่แปลงแล้วออกมา |
| **Explicit Cast vs `Convert.ToInt32()`** | เอาค่าทศนิยมตัวเดียวกัน แปลงเป็น `int` สองวิธีคู่กัน: `(int)ตัวแปร` กับ `Convert.ToInt32(ตัวแปร)` แล้วพิมพ์ทั้งสองค่า — **เลือกค่าตั้งต้นให้เลขหลังจุดทศนิยมตัวแรกเป็น 5 ขึ้นไป** (เช่น `x.5`, `x.6`, `x.9`) ผลลัพธ์สองวิธีถึงจะออกมาไม่เท่ากันจริง (cast ตัดทิ้งเสมอ, `Convert.ToInt32` ปัดเศษเสมอ) — ถ้าเลือกเลขที่ทำให้สองค่าเท่ากัน แปลว่ายังไม่เข้าใจความต่างจริง |
| **ห้ามใช้ `+ - * /` คำนวณ** | แม้แต่จุดเดียว — Operators ยังไม่ได้เรียน (เริ่ม Week 5) ทุกค่าที่พิมพ์ต้องมาจากการ "ประกาศตรงๆ" หรือ "แปลงชนิด" เท่านั้น |
| **String Interpolation** | `$"..."` ทุกบรรทัดที่มีตัวแปร ห้ามต่อสตริงด้วย `+` |
| **Output ออกแบบเอง** | ให้ดูเป็น Stat Card ของเกมจริง — กรอบ ASCII, เส้นคั่น, หัวข้อ, ลำดับยังไงก็ได้ ขอให้อ่านง่ายและดูตั้งใจออกแบบ ไม่ใช่แค่พิมพ์ชื่อตัวแปรกับค่าเรียงกันเฉยๆ |
| **Naming Convention** | ตัวแปรใน `Main` เป็น camelCase, `const` เป็น PascalCase — ชื่อต้องสื่อความหมาย ไม่ใช่ `a`, `b`, `x1` |

## 💡 ตัวอย่าง (ดูไอเดียเฉยๆ — ห้ามลอกทั้งดุ้น ต้องคิดธีม/ชื่อ/ค่า/รูปแบบ output ของตัวเอง)

ตัวอย่างข้างล่างนี้ใช้ธีม "การ์ดสถานะฮีโร่" — ผ่านการคอมไพล์และรันจริงแล้ว แค่โชว์ว่าทำตามตารางด้านบนครบยังไง ไม่ใช่คำตอบที่ต้องเลียนแบบ:

```csharp
using System;

namespace Assignment1
{
    internal class Program
    {
        static void Main(string[] args)
        {
            const string GameTitle = "Starlight Ascension"; // const, PascalCase

            var heroName = "Nova";     // var บน string — ต้องให้ compiler เดาชนิด
            var heroRank = 'A';         // var บน char
            int heroLevel = 15;
            float critChance = 0.35f;
            double staminaPrecise = 87.5;  // เลขหลังจุดเป็น 5 ขึ้นไป
            bool isPlayable = true;

            Console.WriteLine($"===== {GameTitle} =====");
            Console.WriteLine($"Hero Name   : {heroName}");
            Console.WriteLine($"Rank        : {heroRank}");
            Console.WriteLine($"Level       : {heroLevel}");
            Console.WriteLine($"Crit Chance : {critChance}");
            Console.WriteLine($"Stamina     : {staminaPrecise}");
            Console.WriteLine($"Playable    : {isPlayable}");
            Console.WriteLine();

            double heroLevelAsDouble = heroLevel; // implicit — ไม่มี cast
            Console.WriteLine($"Level as double (implicit): {heroLevelAsDouble}");

            int staminaTruncated = (int)staminaPrecise;               // explicit cast
            int staminaRounded = Convert.ToInt32(staminaPrecise);      // Convert
            Console.WriteLine($"Stamina cast (truncates)  : {staminaTruncated}");
            Console.WriteLine($"Stamina Convert (rounds)  : {staminaRounded}");
        }
    }
}
```

ผลลัพธ์จริงจากโค้ดข้างบน (แค่ตัวอย่างการรัน — ของคุณจะออกมาไม่เหมือนนี้เพราะธีม/ชื่อ/ค่าไม่เหมือนกัน และนั่นคือสิ่งที่ถูกต้อง):

```
===== Starlight Ascension =====
Hero Name   : Nova
Rank        : A
Level       : 15
Crit Chance : 0.35
Stamina     : 87.5
Playable    : True

Level as double (implicit): 15
Stamina cast (truncates)  : 87
Stamina Convert (rounds)  : 88
```

สังเกต: `staminaTruncated` (87) กับ `staminaRounded` (88) **ไม่เท่ากัน** — เพราะ `87.5` เลือกให้ตัวเลขหลังจุดเป็น 5 พอดี ถ้าคุณเลือกค่าที่ทำให้สองค่านี้ออกมาเท่ากัน ให้กลับไปอ่านแถว "Explicit Cast vs Convert.ToInt32" ในตารางด้านบนใหม่

## 🎮 Game Context

หน้า Stat Card ในเกมจริง (หน้าเลือกตัวละคร, หน้า inventory, pause menu) ต้องดึงค่าที่เก็บไว้ภายในเกมมาแสดงผล — บางค่าต้องแปลงชนิดก่อนแสดง เช่น ค่าที่เก็บละเอียดเป็นทศนิยมแต่ UI บางจุดต้องการแค่เลขจำนวนเต็มกลมๆ — นักพัฒนาต้องเลือกเองว่าจะ "ตัดทิ้ง" หรือ "ปัดเศษ" ซึ่งให้ผลต่างกันจริง และต้องออกแบบเองว่าจะแสดงข้อมูลให้ผู้เล่นอ่านเข้าใจง่ายแบบไหน — ไม่มีสูตรตายตัว
